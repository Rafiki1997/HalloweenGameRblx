- The official Roblox add-on **Upload to Roblox** v1.0.5 is installed and enabled at
  `%APPDATA%\Blender Foundation\Blender\5.1\scripts\addons\roblox-blender-plugin\`, with its
  dependencies installed. Its saved login is currently empty; the user will log in through the
  add-on's panel before uploads. How it behaves, from its source:
  - It uploads the **selected objects or collections** in the Blender UI. A selected Collection
    becomes one Roblox Model asset with one MeshPart per mesh object inside it. That is how a
    multi-part asset must be structured.
  - It exports FBX with `global_scale=0.01`, `axis_forward='-Z'`, `axis_up='Y'`,
    `use_active_collection=True`, `use_custom_props=True`. Net effect: **1 Blender metre is 1 stud**.
    Use the identical settings in your own exporter so previews and uploads agree.
  - On success it writes the asset ID into a custom property named exactly `Roblox Package ID` on
    the uploaded object or collection. If that property already holds an ID, the next upload
    **updates that asset as a new version instead of creating a new one**. Preserve this property
    across regenerations or you will litter the account with duplicates.
  - Asset type is Model, description "Uploaded from Blender", rate limit 25 uploads per minute.
    Uploaded models appear in Studio under Toolbox, Inventory.
  - Its upload operator needs Blender's window and cannot run headless. Its bundled Open Cloud
    client (`dependencies_private/assets_upload_client.py`, class `AssetsUploadClient`) accepts
    either an OAuth token or an API key and can be imported from a headless script. Do not use the
    saved OAuth refresh token from a script: Roblox rotates refresh tokens, and a script refresh
    would invalidate the add-on's login.
- Roblox Studio is installed. You reach it through the Weppy Roblox MCP (Studio plugin installed),
  which can create and modify instances, insert models by asset ID, start and stop Play, and read
  Output. Screenshots come from `tools/capture_studio.ps1 -StudioProcessId <pid>`.
- Individual meshes are capped at 20,000 triangles. Uploads are capped at 20 MB each.
- The packager `tools/build_place.py` embeds Luau source only. Nothing else goes into the place
  file, so models are loaded at runtime by asset ID, not baked into the place.

## Stage 1. Model in Blender by script

Create `tools/blender/build_assets.py`. Running
`blender --background --python tools/blender/build_assets.py -- --out assets`
must rebuild every asset from primitives and modifiers, apply all modifiers, triangulate, set each
asset's origin to the centre of its base, export one FBX per asset to `assets/exports/`, and save
`assets/town.blend` for the upload step and human inspection.

Rules:
- One Blender **Collection per asset, named exactly as the asset**. Inside it, one mesh object per
  material role, named `<Asset>_<Role>`, Role one of: `Stone`, `Wood`, `Roof`, `Metal`, `Glass`,
  `Glow`, `Accent`, `Foliage`, `Ground`, `Water`, `Collision`. The game colours MeshParts by Role,
  so keep roles honest. `Accent` is recoloured per instance. `Collision` objects are simple boxes
  and wedges the game keeps invisible and collidable; every walkable or blocking surface needs one,
  because visible meshes are non-collidable.
- Before rebuilding, read `assets/manifest.json` and, after rebuilding, write each asset's existing
  `assetId` back onto its Collection as the custom property `Roblox Package ID` (string). This is
  what makes the add-on update in place.
- Model in metres, 1 metre is 1 stud. A Roblox character is 5 studs tall.
- Export settings, identical to the add-on: `global_scale=0.01`, `axis_forward='-Z'`,
  `axis_up='Y'`, `apply_unit_scale=True`, `bake_space_transform=True`,
  `use_mesh_modifiers=True`, `mesh_smooth_type='FACE'`, `object_types={'MESH'}`,
  `use_active_collection=True` with the asset's collection active, `use_custom_props=True`.
  No textures, no image materials, no armatures.
- Watertight, no zero-thickness faces, no n-gons after triangulation, faces outward. Keep
  silhouettes chunky and readable at 40 studs. Bevel only large edges. Stay under the per-asset
  triangle budget and never over 20,000 per mesh object.
- Deterministic: any randomness uses a fixed seed.

Also create `tools/blender/render_previews.py` that renders each asset with Workbench, two views
(front three-quarter and top), moonlit blue backdrop, to `assets/previews/<Asset>_<view>.png`.
Look at every preview and compare it with the matching close-up panel in the concept image before
you move on. Fix what does not read as the thing in the image.

## Stage 2. Upload

### Default lane: the add-on, driven by the user

1. When a zone's assets pass their previews, stop and tell the user: open `assets/town.blend`, in
   the 3D viewport press N, open the **Roblox** tab, log in if the panel asks, choose the creator in
   "Upload to", then in the Outliner select the asset collections you name (list them), and click
   **Upload**. Wait until every listed collection shows a green checkmark, then save the file with
   Ctrl+S and tell you.
2. Then run your `tools/blender/harvest_ids.py` headless against `assets/town.blend`. It reads
   `bpy.data.collections[<Asset>]["Roblox Package ID"]` for every asset, writes `assetId`,
   `uploadedAt`, and the FBX `sha256` into `assets/manifest.json`, and reports any asset that has
   no ID.
3. Because IDs are preserved on the collections, later uploads of a changed asset create a new
   version of the same ID and the manifest does not change. Only new assets need harvesting.

### Optional lane: fully scripted, only if `ROBLOX_API_KEY` is set

Create `tools/upload_assets.py` that imports the add-on's own `AssetsUploadClient` by adding its
`dependencies_private` and `dependencies_public` folders to `sys.path`, constructs it with
`creator=RobloxOpenCloudAssetsV1Creator(user_id=<confirmed id>)` and `api_key` from the
environment variable, and calls `upload_asset_and_wait_for_done_async` with `asset_type` Model,
the asset name, the FBX path, and `asset_id` set to the manifest's existing ID or 0. Write results
to the manifest exactly as the harvest script does, and also write the ID back onto the collection
in `town.blend` so both lanes stay consistent. Never log or store the key.

Moderation can delay an asset's availability by minutes. The runtime must tolerate a load failure.

## Stage 3. Load at runtime

- Generate `src/shared/AssetIds.luau` from the manifest with `tools/gen_asset_ids.py`; never
  hand-edit it. It maps `AssetName -> {Id, Footprint, Roles}`.
- Create `src/shared/Assets/Loader.luau`:
  - `Loader.preload(names)` calls `InsertService:LoadAsset(id)` once per asset on the server, in
    parallel with `task.spawn`, caches the Model, and returns after all finish or after 12 seconds.
  - `Loader.place(name, parent, cf, options) -> Model` clones the cached Model, calls
    `Model:ScaleTo` so `GetExtentsSize()` matches the manifest `Footprint` within 2 percent, pivots
    it to `cf` by its base centre, anchors every part, sets `CanCollide=false` and `CanQuery=false`
    on every visible MeshPart, keeps `Collision` role parts collidable and `Transparency=1`,
    colours each MeshPart by the Role suffix of its name from one palette table, sets `Glow` and
    `Accent` roles to `Enum.Material.Neon`, and applies `options.Accent` to `Accent` parts.
  - If an asset failed to load, `place` builds a placeholder: one dark Part of the footprint size
    with a small warning label, so the game still runs and the acceptance test still passes. Log
    one warning per missing asset with its ID.
- Rewrite `src/server/World.luau` as a layout script: build ground and paving from primitives (big
  flat shapes need no meshes), call `Loader.preload`, place every asset at the coordinates below,
  then build the `W` table exactly as the server expects.
- Calibration: after the first successful load of `StreetLamp`, print its extents. If assets are
  off from their footprints by one constant factor, fix the exporter scale rather than relying on
  `ScaleTo`.
- Confirm MeshPart names survive the upload by listing the children of the first loaded Model
  through the Studio MCP. If Roblox renamed them, adapt the Role detection and say so.
